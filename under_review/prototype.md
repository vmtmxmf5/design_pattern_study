# Prototype Pattern

## 한 줄 정의

기존 객체를 복사(clone)해서 새 객체를 만드는 패턴. 처음부터 새로 만드는 대신, 이미 있는 객체를 복제하고 필요한 부분만 수정한다.

## 언제 사용하는가

- **객체 생성 비용이 클 때**: DB 조회, 네트워크 호출 등으로 초기화가 무거운 객체를 매번 새로 만들기 부담스러운 경우
- **비슷한 객체를 여러 개 만들어야 할 때**: 설정이 거의 같고 일부만 다른 객체를 반복 생성하는 경우
- **구체 클래스에 의존하고 싶지 않을 때**: `clone()`만 호출하면 되므로, 어떤 클래스인지 몰라도 복제 가능

### 실제 사용 사례

- 게임 캐릭터/몬스터 — 기본 스탯이 설정된 원형을 복제 후 이름/위치만 변경
- 문서 템플릿 — 기본 포맷이 완성된 문서를 복제 후 내용만 채움
- Python의 `copy.deepcopy()` — 내장 복제 메커니즘
- 설정 프리셋 — 기본 설정을 복제 후 일부만 커스텀

## 핵심 구조

**Prototype 인터페이스** — `clone()` 메서드를 정의한다. 모든 복제 가능한 객체가 이를 구현.

**복제 과정** — 기존 객체의 상태를 통째로 복사한 새 객체를 반환한다.
- `prototype.clone()` → 동일한 상태의 새 객체 반환
- 필요하면 복제 후 일부 속성만 변경

Python에서는 `copy` 모듈의 `copy()`(얕은 복사)와 `deepcopy()`(깊은 복사)를 활용할 수 있다.

## 주의할 점

- **얕은 복사 vs 깊은 복사**: 내부에 리스트나 딕셔너리 같은 가변 객체가 있으면 얕은 복사 시 원본과 복제본이 같은 객체를 공유함. 의도치 않은 수정이 발생할 수 있으므로 `deepcopy` 사용 고려
- **순환 참조**: 객체 간 순환 참조가 있으면 복제가 복잡해짐. `copy.deepcopy()`는 이를 자동 처리
- **Python에서는 간단**: `copy` 모듈이나 `dataclass` 조합으로 대부분 해결 가능. 별도 Prototype 클래스를 만들 필요가 적음
