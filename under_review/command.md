# Command Pattern

## 한 줄 정의

"해야 할 일"(예: "조명 끄기")을 객체로 만들어서, 나중에 실행하거나 취소하거나 큐에 넣을 수 있게 하는 패턴. 식당에서 주문서를 쓰는 것과 같다 — 웨이트리스는 주문 내용을 몰라도 주방에 전달만 하면 된다.

## 언제 사용하는가

- **실행 취소(Undo)가 필요할 때**: 각 명령이 이전 상태를 기억하고, `undo()`로 되돌릴 수 있음
- **요청을 나중에 실행해야 할 때**: 작업을 큐에 넣어두고 순서대로 처리하거나, 특정 시점에 실행
- **버튼과 동작을 분리하고 싶을 때**: 버튼(Invoker)은 `execute()`만 호출하면 되고, 실제 동작은 명령 객체가 결정
- **여러 동작을 하나로 묶고 싶을 때**: 매크로 명령으로 여러 명령을 한 번에 실행/취소

### 실제 사용 사례

- 스마트홈 리모컨 (슬롯마다 on/off 명령 할당, Undo 지원)
- 텍스트 에디터의 Undo/Redo 스택
- GUI 버튼/메뉴 시스템 (버튼에 Command 객체 할당)
- 작업 큐와 스레드 풀 (명령 객체를 큐에 넣고 워커가 꺼내 실행)

## 핵심 구조

**Command** — 실행할 작업을 감싸는 객체. `execute()`와 `undo()`를 가진다. 내부에 실제 작업을 수행하는 수신자(예: 조명, 에어컨 같은 기기)를 가지고 있다.

**Invoker** — 명령을 실행하는 주체(예: 리모컨). Command의 `execute()`만 호출하면 되고, 어떤 기기가 어떤 동작을 하는지는 모른다.
- `Invoker.set_command(cmd)` → 명령 할당
- `Invoker.press()` → `cmd.execute()` 호출

**Undo** — Command가 실행 전 상태를 저장하고, `undo()`로 복원한다.

## 주의할 점

- **Undo 상태 관리**: 복잡한 수신자의 경우 이전 상태를 정확히 저장하지 않으면 undo가 깨짐. 상태가 많으면 Memento 패턴과 함께 사용 고려
- **Command 클래스 수 증가**: 동작마다 클래스가 필요함. 간단한 경우 Python에서는 람다나 `functools.partial`로 대체 가능
- **매크로의 부분 실패**: 매크로 실행 중 일부만 성공하면, undo 범위를 어디까지 할지 결정해야 함
