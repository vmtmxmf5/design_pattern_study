# Builder Pattern

## 한 줄 정의

복잡한 객체를 단계별로 조립하여, 같은 생성 과정에서 서로 다른 표현의 객체를 만들 수 있게 하는 패턴.

## 언제 사용하는가

- **생성자 파라미터가 너무 많을 때**: 선택적 파라미터가 많아서 생성자 호출이 복잡해지는 경우 (파라미터가 1개, 2개, 3개... 점점 늘어나는 문제)
- **같은 생성 과정으로 다른 결과물을 만들어야 할 때**: 예를 들어 같은 조립 과정으로 돌집, 나무집, 유리집을 만드는 경우
- **복합 객체를 단계적으로 구성해야 할 때**: 트리 구조나 중첩된 객체를 점진적으로 완성해야 하는 경우

### 실제 사용 사례

- 자동차 조립 — 같은 공정으로 세단, SUV, 스포츠카를 생산. 한 빌더는 차량을 만들고, 다른 빌더는 매뉴얼을 만들 수도 있음
- SQL 쿼리 빌더 (`query.select("name").where("age > 20").order_by("name")`)
- HTML/문서 생성기
- 테스트 데이터 팩토리 (테스트용 객체를 단계적으로 조립)

## 핵심 구조

**Builder 인터페이스** — 공통 생성 단계를 정의한다 (`build_walls()`, `build_roof()` 등).

**Concrete Builder** — 각 단계를 구체적으로 구현하여 서로 다른 제품을 만든다.

**Director (선택)** — 빌더의 호출 순서를 정해놓은 객체. 자주 쓰는 조합을 재사용할 수 있게 한다.

- `Director.construct(builder)` → 정해진 순서로 `builder.step1()`, `builder.step2()` 호출
- `builder.get_result()` → 완성된 객체 반환

## 주의할 점

- **클래스 수 증가**: Builder, ConcreteBuilder, Director, Product 등 클래스가 많아질 수 있음
- **단순한 객체에는 과함**: 파라미터가 3~4개뿐이면 생성자로 충분
- **Python에서는 키워드 인자로 대체 가능**: `dataclass`와 키워드 인자 조합이 Builder보다 간결한 경우가 많음
