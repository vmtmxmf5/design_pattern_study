# Command vs Memento

둘 다 **Undo**와 관련되지만, 역할이 다르다. 실제로는 함께 쓰이는 경우가 많다.

## 핵심 차이

| 구분 | Command | Memento |
|------|---------|---------|
| **저장하는 것** | "무엇을 했는지" (행동) | "어떤 상태였는지" (스냅샷) |
| **Undo 방식** | 반대 행동을 실행 | 이전 스냅샷으로 복원 |
| **핵심 역할** | 요청을 객체로 캡슐화 | 상태를 스냅샷으로 보존 |
| **초점** | 실행/취소/재실행 | 저장/복원 |

## 게임으로 비유하면

```
Command = 행동 기록. "앞으로 3칸 이동", "검으로 공격" 같은 행동을 저장.
          Undo = "뒤로 3칸 이동" (반대 행동 실행)

Memento = 세이브 파일. HP=100, 위치=(3,5), 아이템=[검, 방패] 같은 상태 전체를 저장.
          Undo = 세이브 파일 로드 (상태 통째로 복원)
```

## 판단 기준

```
Undo를 어떻게 구현할 것인가?
├── 반대 행동을 실행할 수 있다 → Command
│   (예: "조명 켜기"의 반대는 "조명 끄기")
│   장점: 메모리 효율적, 행동 하나만 기록
│   단점: 반대 행동 정의가 복잡할 수 있음
│
└── 이전 상태 전체를 복원해야 한다 → Memento
    (예: 텍스트 에디터의 전체 내용을 스냅샷으로 저장)
    장점: 복원이 단순, 상태 전체가 정확히 복원됨
    단점: 스냅샷이 크면 메모리 부담
```

## 함께 쓰는 경우

Command의 `undo()`를 구현할 때, 이전 상태를 Memento로 저장하는 조합이 흔하다:

```python
class LightDimCommand(Command):
    def execute(self):
        self._prev_state = self._light.save()  # Memento로 상태 저장
        self._light.dim(50)

    def undo(self):
        self._light.restore(self._prev_state)   # Memento로 복원
```

- **Command**: 행동의 실행/취소 흐름을 관리
- **Memento**: 상태의 저장/복원을 담당

역할이 다르기 때문에 자연스럽게 조합된다.
