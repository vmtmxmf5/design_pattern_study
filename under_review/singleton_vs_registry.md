# Singleton vs Registry

둘 다 **전역 접근**을 제공하지만, 관리하는 대상의 수가 다르다.

## 핵심 차이

| 구분 | Singleton | Registry |
|------|-----------|----------|
| **관리 대상** | 인스턴스 1개 | 여러 객체 (이름으로 구분) |
| **접근 방식** | `AppConfig()` → 항상 같은 인스턴스 | `registry.get("json")` → 이름으로 조회 |
| **목적** | "하나만 존재해야 한다" | "이름으로 찾을 수 있어야 한다" |
| **확장성** | 고정 (하나니까) | 동적으로 등록/삭제 가능 |

## 회사로 비유하면

```
Singleton = 사장님. 회사에 한 명뿐이고, 누구나 "사장님" 하면 찾을 수 있음
Registry  = 사원 명부. 이름으로 검색하면 해당 직원을 찾을 수 있음. 입사/퇴사로 동적으로 변함
```

## 판단 기준

```
전역으로 접근해야 하는 게 뭔가?
├── 인스턴스가 딱 하나만 있어야 함 → Singleton
│   (예: DB 커넥션 풀, 앱 설정 객체)
│
└── 여러 객체를 이름으로 관리해야 함 → Registry
    (예: 직렬화 포맷별 시리얼라이저, URL 라우터)
```

## 주의: 둘 다 전역 상태의 단점을 공유

- 테스트 격리가 어려움 (테스트 간 상태 오염)
- 의존성이 코드에 숨겨짐 (어디서 접근하는지 추적 어려움)
- Python에서는 **모듈 레벨 변수**가 이미 Singleton처럼 동작하므로, 클래스로 구현할 필요가 없는 경우가 많음
