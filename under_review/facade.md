# Facade Pattern

## 한 줄 정의

복잡한 서브시스템의 여러 클래스를 하나의 간단한 인터페이스로 묶어, 클라이언트가 쉽게 사용할 수 있게 하는 패턴. 리모컨 하나로 TV, 스피커, 조명을 한 번에 제어하는 것과 같다.

## 언제 사용하는가

- **복잡한 과정을 한 줄로 끝내고 싶을 때**: 여러 클래스를 조합해야 하나의 작업이 완성되는 경우
- **서브시스템의 세부 사항을 숨기고 싶을 때**: 클라이언트가 내부 구조를 몰라도 기능을 사용할 수 있게
- **팀 간 협업에서 명확한 진입점을 제공해야 할 때**: "이 클래스만 호출하면 된다"는 인터페이스 제공

### 실제 사용 사례

- 주문 처리 시스템 (재고 확인 → 결제 → 배송 → 알림을 한 메서드로 묶음)
- 홈시어터 시스템 (프로젝터, 앰프, DVD, 조명을 `watchMovie()` 하나로 제어)
- ORM 라이브러리 (SQL, 커넥션, 트랜잭션을 하나의 API로 제공)
- 클라우드 SDK (인증, 네트워크, 직렬화를 숨기고 `client.upload()` 하나로 처리)

## 핵심 구조

**Facade** — 서브시스템의 여러 클래스를 알고 있고, 적절한 순서로 호출해서 작업을 완성한다.

**서브시스템** — 각자 독립적으로 동작하는 클래스들. Facade 없이도 직접 사용 가능.

- `Client` → `Facade.do_something()` 호출
- `Facade` 내부에서 → `SubsystemA.step1()` → `SubsystemB.step2()` → `SubsystemC.step3()`

Facade는 서브시스템을 "감추는" 것이 아니라 "쉽게 쓸 수 있게" 해주는 것. 세밀한 제어가 필요하면 서브시스템을 직접 호출해도 된다.

## 주의할 점

- **만능 객체가 되면 안 됨**: 서브시스템의 모든 기능을 Facade에 넣으면 거대한 God Object가 됨. 자주 쓰는 시나리오만 포함할 것
- **서브시스템 접근을 막지 않음**: Facade는 편의를 제공하는 것이지 캡슐화가 아님
- **Adapter와 혼동하지 말 것**: Adapter는 하나의 인터페이스를 변환, Facade는 여러 인터페이스를 하나로 묶어 단순화
