# Mediator Pattern

## 한 줄 정의

객체들이 서로 직접 통신하지 않고, 중재자(Mediator)를 통해서만 소통하도록 하여 결합도를 낮추는 패턴.

## 언제 사용하는가

- **객체 간 의존 관계가 복잡하게 얽혀 있을 때**: A가 B를 알고, B가 C를 알고, C가 A를 아는 식의 그물망 의존이 생긴 경우
- **컴포넌트를 독립적으로 재사용하고 싶을 때**: 특정 컴포넌트가 다른 컴포넌트에 직접 의존하면 단독으로 재사용할 수 없음
- **여러 컴포넌트의 상호작용을 한 곳에서 관리해야 할 때**: 상호작용 로직이 여기저기 흩어져 있으면 수정이 어려움

### 실제 사용 사례

- 항공 관제탑 — 조종사들은 서로 직접 소통하지 않고 관제탑을 통해 이착륙 순서를 조율
- 채팅방 — 사용자들이 서로에게 직접 메시지를 보내지 않고 채팅방(Mediator)을 거침
- GUI 다이얼로그 — 버튼, 텍스트 필드, 체크박스가 서로 직접 참조하지 않고 다이얼로그 클래스가 조율

## 핵심 구조

**Mediator** — 컴포넌트들의 통신을 중개하는 인터페이스. 컴포넌트가 이벤트를 보내면 적절한 대상에게 전달한다.

**Component** — Mediator 인터페이스만 알고, 다른 컴포넌트는 모른다.

- `Component` → `mediator.notify(self, event)` 이벤트 전달
- `Mediator` → 이벤트에 따라 다른 컴포넌트의 메서드 호출

## 주의할 점

- **God Object 위험**: 시간이 지나면 Mediator에 모든 로직이 집중되어 거대한 클래스가 될 수 있음
- **Observer와의 차이**: Observer는 일대다 단방향 알림이고, Mediator는 다대다 양방향 조율
