# Singleton Pattern

## 한 줄 정의

클래스의 인스턴스가 하나만 존재하도록 보장하고, 그 인스턴스에 대한 전역 접근점을 제공하는 패턴.

## 언제 사용하는가

- **공유 리소스를 하나로 제한해야 할 때**: DB 커넥션 풀, 로깅 시스템, 설정 관리 객체처럼 여러 곳에서 접근하지만 인스턴스는 하나여야 하는 경우
- **전역 변수보다 안전한 접근이 필요할 때**: 전역 변수는 누구나 덮어쓸 수 있지만, Singleton은 생성을 제어할 수 있음

### 실제 사용 사례

- DB 커넥션 풀
- 로깅 시스템 (`logging.getLogger()`)
- 설정/환경 변수 관리 객체
- 정부 — 한 나라에 공식 정부는 하나뿐이고, "X국 정부"라는 이름으로 전역 접근

## 핵심 구조

**인스턴스 제어** — 생성자를 외부에서 직접 호출하지 못하게 막고, 정적 메서드를 통해서만 인스턴스를 얻는다.

**지연 생성** — 첫 호출 시에만 인스턴스를 만들고, 이후 호출에서는 이미 만든 인스턴스를 반환한다.

- `Singleton.get_instance()` → 최초 호출 시 생성, 이후 캐싱된 인스턴스 반환

## 주의할 점

- **단일 책임 원칙 위반**: "인스턴스를 하나로 제한"과 "본래 비즈니스 로직" 두 가지 책임을 동시에 짐
- **테스트 어려움**: 전역 상태를 가지므로 테스트 간 격리가 어려움. 테스트마다 인스턴스를 리셋해야 함
- **멀티스레드 환경**: 동시에 `get_instance()`를 호출하면 인스턴스가 두 개 생길 수 있음 → 락 필요
- **Python에서는 모듈이 이미 Singleton**: 모듈 레벨 변수는 한 번만 초기화되므로, 굳이 클래스로 구현하지 않아도 되는 경우가 많음
