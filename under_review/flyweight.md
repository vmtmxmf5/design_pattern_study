# Flyweight Pattern

## 한 줄 정의

대량의 유사한 객체들이 공통 데이터를 공유하도록 하여, 메모리 사용량을 줄이는 패턴.

## 언제 사용하는가

- **동일한 데이터를 가진 객체가 대량으로 존재할 때**: 수만 개의 나무, 총알, 글자 등 비슷한 객체가 메모리를 과도하게 차지하는 경우
- **객체의 상태를 고유 상태와 공유 상태로 분리할 수 있을 때**: 변하지 않는 부분(글꼴, 색상)과 변하는 부분(위치, 크기)을 나눌 수 있는 경우

### 실제 사용 사례

- 활자 시스템 — 글자마다 폰트/크기/스타일은 공유하고, 페이지 위 위치만 개별 관리
- 게임 파티클/총알 — 스프라이트, 색상은 공유하고 좌표/속도만 개별
- 캐시 시스템 — 동일한 데이터를 여러 곳에서 참조

## 핵심 구조

**고유 상태(Intrinsic)** — 변하지 않는 공유 데이터. Flyweight 객체에 저장되며 불변이다.

**외부 상태(Extrinsic)** — 객체마다 다른 맥락 데이터. 메서드 호출 시 파라미터로 전달한다.

**Flyweight Factory** — 기존 Flyweight 풀을 관리. 이미 있으면 재사용하고, 없으면 새로 만든다.

- `Factory.get_flyweight(shared_state)` → 풀에서 검색, 없으면 생성 후 캐싱
- `Flyweight.operation(extrinsic_state)` → 공유 데이터 + 외부 데이터로 작업 수행

## 주의할 점

- **메모리 절약 vs CPU 비용**: 외부 상태를 매번 계산/전달해야 하므로 CPU 사용량이 늘어날 수 있음
- **코드 복잡도 증가**: 상태를 분리하는 작업이 추가되어 코드가 읽기 어려워질 수 있음
- **실제로 메모리 문제가 있을 때만 적용**: 프로파일링 없이 선제적으로 적용하면 불필요한 복잡성만 추가됨
