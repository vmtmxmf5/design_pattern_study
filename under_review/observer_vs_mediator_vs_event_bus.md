# Observer vs Mediator vs Event Bus

셋 다 객체 간 **통신**을 다루는 패턴이지만, 통신 방식과 결합도가 다르다.

## 핵심 차이

| 구분 | Observer | Mediator | Event Bus |
|------|----------|----------|-----------|
| **관계** | 1:N (일대다) | N:N (다대다) | N:N (다대다) |
| **방향** | 단방향 알림 | 양방향 조율 | 단방향 발행/구독 |
| **결합도** | Subject가 Observer 목록을 관리 | Mediator가 컴포넌트들을 알고 있음 | 발행자와 구독자가 서로 모름 |
| **로직 위치** | 각 Observer가 자체 처리 | Mediator 안에 조율 로직 집중 | 구독자가 자체 처리 |

## 회사로 비유하면

```
Observer  = 팀장이 팀원들에게 공지. 팀장은 팀원 목록을 알고, 팀원은 공지를 받으면 알아서 처리
Mediator  = 프로젝트 매니저. 디자이너, 개발자, QA가 서로 직접 대화하지 않고 PM을 통해 조율
Event Bus = 사내 게시판. 누가 글을 올렸는지, 누가 읽는지 서로 모름. 관심 있는 게시판만 구독
```

## 판단 기준

```
"누가 누구를 아는가?"
├── 발행자가 구독자 목록을 직접 관리 → Observer
├── 중재자가 모든 컴포넌트를 알고 조율 로직을 가짐 → Mediator
└── 아무도 서로를 모름, 이벤트 이름으로만 연결 → Event Bus
```

## 언제 어떤 걸 쓰나

- **Observer**: 데이터 변경 → 여러 뷰 갱신 (MVC의 Model→View)
- **Mediator**: 여러 컴포넌트가 복잡하게 상호작용하는 경우 (채팅방, GUI 다이얼로그)
- **Event Bus**: 모듈 간 완전한 분리가 필요한 경우 (마이크로서비스, 플러그인 시스템)
