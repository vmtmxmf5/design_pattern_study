# Iterator Pattern

## 한 줄 정의

컬렉션의 내부 구조를 노출하지 않으면서, 요소를 하나씩 순회할 수 있는 통일된 방법을 제공하는 패턴. Python의 `for item in collection`이 바로 이 패턴이다.

## 언제 사용하는가

- **내부 구조가 다른 컬렉션을 동일한 방식으로 순회해야 할 때**: 리스트, 딕셔너리, 트리 등을 하나의 인터페이스로 탐색하고 싶은 경우
- **내부 구현을 숨기고 싶을 때**: 배열인지 연결 리스트인지 몰라도 순회할 수 있어야 하는 경우
- **여러 순회 방식이 필요할 때**: 같은 컬렉션에 대해 정방향, 역방향, 필터링 등 다양한 탐색 전략 제공

### 실제 사용 사례

- Python의 `__iter__`/`__next__` 프로토콜 (모든 for 루프의 기반)
- 식당 메뉴 통합 (배열 vs 리스트로 저장된 메뉴를 동일하게 순회)
- 데이터베이스 커서 (대량 결과를 한 행씩 가져오기)
- 파일 라인 읽기 (`for line in file`)

## 핵심 구조

**Iterator** — 현재 위치를 추적하며 요소를 하나씩 꺼내주는 객체.
- `has_next()` → 다음 요소 존재 여부
- `next()` → 다음 요소 반환 및 위치 이동

**Collection** — 자신의 내부 구조를 아는 Iterator를 생성하여 반환.
- `create_iterator()` → `Iterator` 반환

클라이언트는 Iterator 인터페이스만 사용하므로, 컬렉션이 리스트든 딕셔너리든 **동일한 코드로 순회** 가능.

## 주의할 점

- **Python에는 이미 내장**: `__iter__`/`__next__`를 구현하면 for 루프에서 바로 사용 가능. 별도 Iterator 클래스보다 Python 프로토콜 활용이 자연스러움
- **순회 중 컬렉션 변경 금지**: 순회하는 도중 원본이 변경되면 예측 불가능한 결과 발생
- **한 번 소진되면 재사용 불가**: 다시 순회하려면 새 Iterator를 생성해야 함
- **제너레이터 활용**: Python에서는 `yield`를 사용한 제너레이터(값을 하나씩 만들어주는 함수)가 Iterator의 간결한 대안
