# Registry Pattern

## 한 줄 정의

객체를 이름으로 등록해두고, 어디서든 꺼내 쓸 수 있는 전역 저장소 패턴

```python
registry.register("build", BuildAgent())   # 이름으로 등록
agent = registry.get("build")              # 어디서든 이름으로 꺼내 쓴다
```

## 언제 사용하는가

- **이름으로 객체를 검색해야 할 때**: 플러그인, 핸들러, 서비스 등을 문자열 키로 등록하고 조회하는 경우
- **객체 생성과 사용을 분리하고 싶을 때**: 등록 시점과 사용 시점이 다른 경우 (예: 앱 초기화 시 등록, 요청 처리 시 조회)
- **확장 가능한 플러그인 구조가 필요할 때**: 새 플러그인을 코드 수정 없이 등록만으로 추가하고 싶은 경우

### 실제 사용 사례

- Python 데코레이터 기반 라우터 (`@app.route("/users")` → 핸들러 등록)
- 직렬화 포맷 레지스트리 (JSON, YAML, TOML 시리얼라이저를 이름으로 등록/조회)
- 서비스 로케이터 — DI 컨테이너의 단순한 형태

## 핵심 구조

**등록** — 키-값 쌍으로 객체를 저장소에 넣는다.
- `Registry.register(name, obj)` → 등록

**조회** — 키로 객체를 꺼낸다.
- `Registry.get(name)` → 등록된 객체 반환

내부적으로는 딕셔너리 하나로 구현되는 경우가 대부분이다.

## 주의할 점

- **전역 상태 문제** — 어디서든 접근 가능하므로, 한 곳에서 등록/수정하면 다른 곳에도 영향이 간다. 테스트에서 특히 문제됨
- **타입 안전성 부족**: 문자열 키로 조회하므로, 오타나 누락을 컴파일 타임에 잡을 수 없음
- **DI 컨테이너와의 차이**: Registry는 단순 조회만 제공하고, DI(의존성 주입) 컨테이너는 객체 간 의존성 연결과 생명주기 관리까지 담당 (DI는 고급 주제이므로 나중에 배워도 됨)
