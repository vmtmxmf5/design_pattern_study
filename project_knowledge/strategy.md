# Strategy Pattern

## 한 줄 정의

알고리즘(행동)을 별도의 클래스로 분리하고, 실행 시점에 원하는 알고리즘을 골라 끼워 넣을 수 있게 하는 패턴.

## 언제 사용하는가

- **같은 작업을 여러 방식으로 처리해야 할 때**: 결제(카드/계좌이체/포인트), 정렬(퀵/머지/버블), 인증(JWT/OAuth/세션) 등 동일한 목적의 알고리즘이 여러 개 존재할 때
- **if/else나 switch로 분기가 늘어날 때**: 조건 분기 대신 각 분기를 독립된 Strategy 클래스로 분리하여 관리
- **런타임에 행동을 교체해야 할 때**: 실행 중에 알고리즘을 바꿔야 하는 경우 (예: 게임 캐릭터의 무기 교체)
- **상속 대신 조합을 쓰고 싶을 때**: 부모 클래스에 행동을 넣으면 모든 자식이 영향받는 문제를 피하고 싶을 때

### 실제 사용 사례

- 결제 수단 선택 시스템
- 파일 압축 (zip, gzip, bz2 등 알고리즘 교체)
- 할인 정책 (정가/퍼센트 할인/고정 금액 할인)
- 로그 출력 대상 변경 (파일/콘솔/외부 서비스)

## 핵심 구조

**구독 관리** — Context는 Strategy 인터페이스만 알면 되고, 구체적인 알고리즘 클래스를 몰라도 된다.

**실행 흐름** — Context가 작업을 수행할 때 자신이 직접 처리하지 않고, 가지고 있는 Strategy 객체에게 위임한다.

- `Context.set_strategy(strategy)` → 알고리즘 교체
- `Context.execute()` → `Strategy.do_something()` 호출

## 주의할 점

- **Strategy가 2~3개뿐이고 변경될 일이 없다면** 패턴 적용이 오히려 과함. 단순 if/else가 나을 수 있음
- **클래스 수 증가**: Strategy마다 클래스를 만들어야 하므로, 간단한 경우 Python에서는 함수를 Strategy로 넘기는 것도 방법
- **Context와 Strategy 간 데이터 전달**: Strategy가 Context의 내부 상태에 접근해야 한다면 결합도가 높아질 수 있음
